### 2-1. 공통 주의

- **1-08 주의**: 설명은 "2025년 5월 ~ 현재"인데 열 예시 `base_year_month` = 201701. 예시값만 옛 값일 가능성 — 확인 못 함.
- **1-12·1-14 주의**: 열 비고의 `지역구분`은 7개 권역(제주시 중부(동)·(서) 포함), 하지만 같은 시트의 [참고1] 지역구분 목록은 6개(제주시·제주시 동부·제주시 서부·서귀포시·서귀포시 동부·서귀포시 서부). 열 예시 `제주시 중부(서)`도 6개 목록에 없음 — 워크북 안에서 불일치 [확인].
- **시간대 구간 불일치**: 카드 시간대(1-14)는 오전·점심·오후·저녁·밤 5구간, 외식업 고객 이용(1-21·1-22)은 00~06, 06~09, 09~12, 12~15, 15~18, 18~21, 21~24 7구간 — 서로 다른 구간이라 직접 비교하면 안 됨 [확인].
- **연령대 구간 불일치**: 카드(1-08 등)는 10·20·…·70 + NA, 외식업 고객(1-21·1-22)은 `20(이하)`·30·…·`70(이상)` 표기 [확인].
- **정류소 ID 키 불일치**: 센터 3-03·3-04의 `bus_station_id`는 "7자리"(명세), 공공데이터포털 "버스정류소현황"(15010850)의 `정류소아이디`는 9자리(예: 406001167) [확인]. 두 체계가 같은 키인지 확인 못 함 — 조인 전에 확인 필요.
- **시군구 코드 대응**: 외식업(1-19·1-22·1-24) 예시 `city_cd` 5011·5013 ↔ 제주시·서귀포시 대응은 명세 예시만 보면 불명확. 법정동코드 예시(50110101 = 일도일동, 제주시)와 5-01 관측소 예시(중문, 법정동리코드 5013011200)로 보면 5011 = 제주시, 5013 = 서귀포시 [추정].
- **제공처 불일치**: 4-11은 목록 시트 "SKT, KT", 워크북 상세 "제주특별자치도(SKT)", PDF "SKT, KT". 4-15도 같은 차이 [확인].
- **1-18 주석**: 법정동별·500m격자 단위 합산 값은 개인정보보호법에 따라 k값 3 미만을 제외해서 합계가 다를 수 있다고 명시 [확인].

## 9. 재현 메모

- 목록: `GET https://jejudatahub.net/api/ndapTable/list` (JSON).
- 명세 워크북: `https://jejudatahub.net/document/데이터명세서_kr.xlsx` (SPA `/center/data` 번들의 `fileUrl`).
- 데이터 목록: `GET https://jejudatahub.net/api/data?...&length=1300&isPaging=true` (파라미터 전체 필요, 빈 값도 포함). 상세: `GET /api/data/view?id=<id>`. 파일: `GET /api/file?id=<fileInfo.id>&fileId=<fileInfo.fileId>`.
- 공지 48 첨부 PDF: `GET /api/file?id=6099&fileId=4982`.
- 공공데이터포털 파일 다운로드(페이지 JS 흐름과 동일): `POST /tcs/dss/selectFileDataDownload.do` → `POST /cmm/cmm/check-limit.json` (needCaptcha가 false일 때만) → `GET /cmm/cmm/fileDownload.do?atchFileId=&fileDetailSn=&dataNm=`. 캡차가 필요한 경우는 중단한다는 원칙으로 실행함.
- 명세 열 파싱: 워크북 시트마다 "컬럼명" 또는 "Column 명" 헤더 행을 찾아 그 아래 번호행을 읽음. 결과는 작업 PC의 `docs/src/spec-columns-derived.json`(공개 저장소에는 넣지 않음).

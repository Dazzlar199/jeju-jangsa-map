# 데이터 활용 명세 (초안)

기준 문서: [docs/data-spec.md](data-spec.md)(열 명세·반출 기준·공개 파일 조사, 2026-10-30), 반출 기준 PDF(제주데이터허브 공지 48 첨부, 2026.09.01 개정; 재배포 조건을 확인하지 못해 PDF 사본은 저장소에 넣지 않음). **[확인]** 은 원본에서 직접 본 것, **[추정]** 은 추론, **[확인 필요]** 는 센터·제공처에 물어야 하는 것.

- 업종은 센터 카드 표 업종코드 42개 중 9개를 쓴다: 카페=I56220(비알콜 음료점업), 한식=I56111, 중식=I56112, 일식=I56113, 양식=I56114(서양식), 간이음식=I56192(피자·햄버거·샌드위치), 주점=I56211+I56219, 편의점=G47122, 베이커리=G47215(빵 및 과자류 소매업) [확인: 1-08 시트 [참고2]]. 치킨·분식은 코드에 없다.
- 시간대 구분은 카드 표 기준(오전 07-11시, 점심 11-14시, 오후 14-18시, 저녁 18-22시, 밤 22-07시)이다. 외식 POS 고객 표(7구간)와 직접 비교하면 안 된다 [확인].
- **법정동→행정동**: 카드 표는 법정동(bjd), 유동인구는 행정동이다. `config/tables.yaml` 의 `legal_to_admin`(초안, 확실한 것만)으로 맞추고 못 맞춘 동은 경고 후 뺀다 [확인 필요: 센터 행정구역 대응표].
- 외식업 POS(1-19~1-29)·단기체류 외국인 유동인구(4-15)는 1차 동작본에서 쓰지 않는다(남은 일).

## 3. 가상 데이터
`scripts/make_synthetic.py`(고정 시드 20261030)가 센터 명세의 열 이름·값 형식으로 만든다: 43개 읍면동(제주시 26·서귀포시 17), 업종 9개, 2024-10~2026-09 월별, 이용자구분(제주도민·내국인), 법정동 쪼개기, 주점 코드 2개 분할. 관광 읍면은 여름·주말이 높고 도심은 평일 점심·저녁이 높으며, 추자·우도 등은 매장이 적어 10 미만 가림이 실제로 걸린다. 모든 파일은 `가상_` 접두사와 `데이터구분=가상` 열이 있고, 화면·보고서에 "가상 데이터" 를 표시한다. 시간대·요일 표는 최근 12개월, 유동인구는 달마다 4일×4시각 표본이다.

## 4. 전처리·분석 흐름
CSV 읽기(인코딩 자동) → 열 자동 매핑(`csv_profile`: 별칭·철자 유사도) → 값 정리(연월 YYYY-MM, 숫자, 법정동→행정동, 업종코드·이름→앱 업종) → 겹치는 키 합산(성별·연령·이용자구분) → DuckDB 메모리 표 → 계획 SQL(`sql_run`: SELECT·집계·LIMIT 강제) → `export_gate`(반출 기준) → 그래프·해설 → 보고서·분석 기록. 개인 자료는 디스크에 쓰지 않는다.

## 5. 반출 기준과 구현 (`config/export_rules.yaml`)

| 기준(PDF) | 구현 |
|---|---|
| 원본·발췌 반출 불가 | 결과 행이 원천 표의 60% 초과 또는 200행 초과면 차단, `biz_num`·`ent_nm` 같은 기업 식별 열이 든 원본 행 CSV 는 올리기 거절, 식별 열(격자·좌표·카드번호) 차단 |
| 단순집계는 10 미만 수치 불포함 | 근거 건수 열(`…_cnt`)이 10 미만인 행의 합계·평균·건수를 삭제처리(`small_cell_method`: delete / category「10 미만」 / mask) |
| 응용집계(지수·비율·순위)는 수치 포함 가능 | 지수·순위·비율 열(`…_idx`, `…_rank`, `…_per_…`, `…_pct`)은 보임. 자체 강화로 근거 3 미만이면 가림(`applied_min_support`) |
| 시각화는 PNG/JPG 만 | 보고서 그래프는 PNG, "그래프를 PNG 로 저장" 버튼. SVG·HTML 그래프를 반출용으로 만들지 않음 |
| csv·txt·엑셀 반출 원칙 불가(비씨카드·SKT 등) | 원본 불가 표 결과는 허용 형식이 `png`·`report` 뿐이라 CSV 저장 버튼을 숨김. 반출 가능 표(버스·날씨)·공개 실데이터 결과에만 CSV 버튼 |
| 반출 가능 표(버스·날씨)는 원본까지 가능 | `export_level: open` 표는 10 미만 가림을 적용하지 않음 |
| 소스코드에 데이터 샘플 출력 금지 | 분석 기록(`runs/*.json`)에는 SQL·행 수·판정만 저장, 데이터 값 없음 |
| 1-18 주석: 합산 값은 k 3 미만 제외 | 위 `applied_min_support: 3` 과 같은 취지 |

**문서 안 충돌 — 센터 질의 필요.** 반출 기준 4쪽은 "원본 제공이 불가한 데이터는 제공단위(블록·집계구·동·구 등)에 대한 총합·평균 등 통계처리 데이터도 반출 불가가 원칙"이라 하고, 10쪽은 같은 표들의 단순집계를 "10 미만 수치 불포함 시 반출 가능"이라 한다. 읍면동 단위 합계·평균을 결과물에 넣어도 되는지 이 문서만으로 확정할 수 없어 **엄격 모드(`strict_mode: true`, 기본)**로 만들었다: 원본 불가 표에서 나온 결과 중 합계·평균·건수는 **센터 안 화면에서만** 보이고, LLM 전송·보고서·PNG 로 나가는 표에는 지수·비율·순위(응용집계)만 남는다. 센터가 10쪽대로 허용한다고 답하면 `strict_mode: false` 한 줄로 바꾼다(그때도 10 미만은 가려진 채 나간다). 그 밖에 센터에 물을 것: ① 지수·순위가 소수 읍면동 값을 역산하게 하지 않는지(자체 강화 기준 3이 충분한지) ② 법정동→행정동 대응표 ③ 영리 목적 사용 시 제공처 협의(PDF) vs 통계정보 상업적 활용 허용(약관 8조) ④ 결과물 소유권(규칙 탭 "센터 소속" vs 동의사항 "저작권은 참가자").

요약

문제제주에서 가게를 내려는 사람은 동네별 매출·유동인구·경쟁·폐업 자료를 한 번에 보기 어렵다. 센터에는 표가 73종 있으나, 어떤 표를 어떤 조건으로 받아 어떻게 묶는지는 비전문가가 알기 어렵다. 반출 불가 데이터는 외부 LLM으로 보낼 수도 없다.
해결질문 한 문장을 쓰면 계획 에이전트가 필요한 표와 "센터에서 받아 올 CSV 체크리스트"를 안내하고 분석 SQL을 정한다. 로컬 도구(DuckDB)가 계산하고, 반출 기준 검사기(export_gate)를 통과한 집계만 해설 에이전트가 쉬운 문장·근거표 번호·한계로 풀어 준다. 1장 보고서와 분석 기록이 함께 나온다.
현황1차 동작본 구현·자동 테스트 86개 통과(가상 데이터 + 공개 실데이터). 센터의 실제 CSV로는 아직 돌려 보지 못했다(센터 방문 전).

1. 구현목표

대응 평가항목 분석 주제의 타당성과 창의성(15) · 일부 편의성 및 실용성(25)

1.1 분석 주제

"제주 동네 창업·장사 진단" — 제주에서 가게를 열려는 예비 창업자와 자영업자가 "이 동네에서 이 업종을 하면 어떤가", "우리 가게 매출이 동네 평균보다 어떤가"를 한 문장으로 묻고, 근거가 붙은 쉬운 답을 받는다.

  • 왜 이 주제인가: 창업·자영업은 도민 체감이 크고, 카드·유동인구·휴폐업·날씨 표를 겹쳐야 답이 나온다. 표 하나로는 답이 안 되므로 "데이터 탐색부터 분석 결과 제공까지"를 하는 Agent의 일이다.
  • 활용 목적: 입지·경쟁·시간대·계절·내 가게 비교 다섯 질문에 숫자 근거를 준다. 창업 여부는 대신 정하지 않고, "확인한 신호 4개 중 유리 2개, 불리 2개"처럼 근거표와 함께 보여 준다.
  • 참신성: 반출 불가 데이터 환경에서 외부 LLM을 어디까지 쓸 수 있는지를 설계로 풀었다. 운영진 답변(2026-10-30)의 "반출 기준을 충족하는 범위의 집계값은 전송 가능"을 코드로 구현했다.

2. 서비스 제안

대응 평가항목 편의성 및 실용성(25) · 필수 데이터 활용 적절성(20)

2.1 데이터 활용 개요

센터 PC에서 이용자가 센터 표를 CSV로 내려받아 앱에 올리면, 앱이 열을 자동으로 맞춰 로컬 DuckDB에서 질문에 맞는 집계를 한다. 센터 데이터 시스템에는 접속하지 않는다(운영진 답변: API 직접 연결 미지원). 공개 실데이터 4개 파일(5개 표)은 앱에 들어 있어 센터 표 없이도 [실데이터] 단계가 돈다. 자세한 표는 4장.

2.2 핵심 기능

#기능내용
1질문 이해 확인질문에서 질문 유형·동네·업종을 읽고 "이렇게 이해했어요"로 보여 준다. 틀리면 목록에서 고쳐 다시 분석한다. 동네나 업종을 못 읽으면 확인 전에는 분석하지 않는다.
2받아 올 CSV 체크리스트필요한 센터 표의 번호·이름·받을 조건(기간·업종코드 등)과 불러온 상태를 표로 안내한다(그림 2).
3CSV 올리기·열 자동 맞춤CP949·UTF-8 자동 판별, 열 이름 별칭·철자 유사도로 맞춤, 성별·연령대·이용자구분은 합산. 맞지 않으면 이유와 직접 고르기 화면. 기업 원본 행(사업자번호·기업명)은 올릴 수 없다.
4결과 해설한 줄 결론, 쉬운 문장 요약(문장마다 [근거표 N]), 그래프, 근거표, 한계 문장(그림 5, 6).
5내 가게 비교월 매출 두 열 CSV를 올리면 동네 평균과 견준다. 금액은 이 화면 안에서만 쓰고 LLM·보고서로 나가지 않는다.
6보고서1~2쪽 HTML(그래프는 PNG, 출처 문구·가상 데이터 표시 포함). 센터 밖 반출은 센터 심사를 거친다.
7분석 기록·전송 미리보기실행 SQL·사용 파일·gate 결과·LLM 호출 수·예상 비용. LLM에 실제로 가는 글을 미리 보여 준다(그림 4).
8개인 자료 삭제"올린 자료 모두 삭제" 한 번으로 올린 CSV와 저장한 보고서를 지운다. 올린 CSV는 처음부터 디스크에 쓰지 않는다.

2.3 편의성 (IT 비전문가 도민 기준)

  • 설치·실행은 install.bat, run.bat 더블클릭이 전부다. 명령어를 쓰지 않는다.
  • 예시 질문 버튼을 누르면 바로 분석한다. 직접 쓸 때는 "동네 + 업종 + 궁금한 것" 한 문장이면 된다.
  • "어떤 표를 받아야 하나"를 앱이 알려 준다. 용어는 "지수=읍면동 평균이 100", "비공개=근거 10 미만" 식으로 화면에 풀어 쓴다.
  • 가상/실데이터를 단계마다 색 딱지로 구분한다. 키가 없거나 연결이 안 되면 자동으로 오프라인 방식으로 답한다.

2.4 분석 데이터 활용 방안 (센터 현장)

  • 센터 방문 도민의 데이터 상담 창구용 도구: 질문을 받으면 체크리스트대로 받을 CSV를 안내한다. API 비용 없이 상시 운영(오프라인 모드)하고, LLM 모드는 센터가 키를 넣을 때만 켠다.
  • 확장 계획: 외식업 POS 표(1-19~1-29), 단기체류 외국인 유동인구(4-15)를 질문 유형에 추가. 현재는 쓰지 않는다.

4값 정리연월 YYYY-MM(202410·2024.10·2024-10-15 모두), 쉼표 제거, "제주시 애월읍"→"애월읍", 업종코드·이름→앱 업종 9개, 법정동→행정동
5합산겹치는 키(성별·연령대·이용자구분·날짜·시각)를 합산해 읍면동×업종×월 단위로 맞춘다.
6분석DuckDB 메모리 표에 올려 계획 SQL 실행(sql_run의 안전 검사 통과). 개인 자료는 디스크에 쓰지 않는다.
7반출 검사export_gate(4.5), 통과한 표만 그래프·해설·보고서·LLM으로 간다.
8기록분석 기록 저장(SQL·파일·행 수·판정, 데이터 값 없음)

4.4 가상 데이터

센터 표 실제 CSV를 받기 전에 개발·시연하기 위해 scripts/make_synthetic.py(고정 시드 20261030)가 센터 명세의 열 이름·값 형식으로 만든다. 43개 읍면동, 업종 9개, 2024-10~2026-09 월별. 관광 읍면은 여름·주말이 높고 도심은 평일 점심·저녁이 높게, 추자·우도 등은 매장이 적어 "10 미만" 가림이 실제로 걸리게 맞췄다. 모든 파일에 가상_ 접두사와 데이터구분=가상 열이 있고, 화면·보고서에 "가상 데이터"를 표시한다. 같은 시드는 바이트 단위로 같은 파일을 만든다(테스트). 가상 데이터는 제출물에 넣고, 설치 때 만든 파일을 쓴다(용량 때문에 저장소에는 큰 파일을 넣지 않음).

6.2 하지 못한 검증 (제출 전 수행 예정)

  • 센터의 실제 CSV로 실행: 열 이름은 명세서로 맞췄으나 실제 파일로는 못 돌렸다. 다르면 config/tables.yaml의 별칭 한 곳에서 고친다.

1반출 기준 문서의 4쪽과 10쪽이 다르다. 4쪽은 원본 불가 데이터의 읍면동 단위 총합·평균도 반출 불가가 원칙이라 하고, 10쪽은 같은 표의 단순집계를 10 미만 불포함 시 반출 가능이라 한다. 어느 쪽인가?엄격 모드(4쪽 우선)가 기본. 센터가 10쪽대로 허용하면 설정 한 줄(strict_mode: false)로 바꾼다.
2응용집계(지수·순위)가 소수 읍면동 값을 역산하게 하지 않는가? 자체 기준(근거 3 미만 가림)이 충분한가?자체 강화 기준 3 적용
3카드 표(법정동)와 유동인구(행정동)를 맞출 센터의 행정구역 대응표가 있는가?초안 대응표 사용
4센터 표의 실제 CSV 열 이름·인코딩·행 수, 내려받기 용량·건수 한도는?명세서 열 이름 기준, 별칭으로 흡수
5영리 목적 사용 시 제공처 협의(PDF)와 통계정보 상업적 활용 허용(이용약관 8조)의 관계는?대회·시연은 비영리 전제
6결과물 소유권: 규칙 탭 "센터에 소속"과 동의사항 "저작권은 참가자"의 충돌을 어떻게 읽는가?외부 코드를 복사하지 않고 본 대회용으로 새로 작성
7센터 3-03·3-04의 정류소 ID(7자리)와 공공데이터포털 버스정류소 ID(9자리)가 같은 체계인가?ID로 조인하지 않음
8센터 PC의 Python 3.11 설치, PyPI 접근 또는 5.4 패키지 사전 설치, 브라우저 종류·버전, LLM API 도메인 3개 허용은 가능한가?5.3·5.5에 요구사항 명시
9이용자가 만든 보고서(HTML·PNG)를 센터 밖으로 가져가는 반출 신청 절차와 형식 제한은?보고서는 PNG·지수·비율 중심으로만 구성
10공개 파일 이용조건: 서귀포시 휴게음식점 현황의 라이선스, BC카드 자료의 공공누리 유형(자유이용 vs 4유형)은?이용조건 미확인·불일치를 4.2에 명시

7.1 사용 AI 모델

구분내용
앱 실행 중(런타임)오프라인 모드(기본): AI 모델 없음. LLM 모드(선택): gpt-4o-mini(OpenAI), claude-haiku-4-5(Anthropic), gemini-2.5-flash(Google) 중 이용자가 고른 하나. 모델 이름은 화면에서 바꿀 수 있다.
개발 과정코드·문서 초안 작성에 생성형 AI 코딩 도구를 사용했다(저장소 커밋 기록에 공동 작성자 Claude Sonnet 5.5 표기). 구현 범위와 사실은 저장소 파일과 테스트로 확인한다. [팀 확인 후 도구·모델 표기 확정]

7.2 AI 활용 범위

단계AI를 쓰는가범위
질문 해석·계획LLM 모드에서만질문 유형·동네·업종·분석 단계·SQL 제안. 허용 목록·SQL 안전 검사를 통과해야 실행. 오프라인은 규칙
데이터 계산아니오DuckDB·pandas가 계산(AI 생성 숫자 없음)
반출 검사아니오규칙 코드
해설 문장LLM 모드에서만통과한 반출용 표로 쓴다. 숫자가 표에 없으면 템플릿 해설로 교체
그림·이미지아니오그래프는 코드로 그린다. 이 문서의 Agent 구조 도식은 직접 그렸고, AI 생성 이미지를 쓰지 않았다. 화면 그림은 앱의 실제 캡처

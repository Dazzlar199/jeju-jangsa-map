# LLM 경계: 무엇을 보내고 무엇을 안 보내는가

운영진 답변(2026-10-30): 반출 불가 데이터의 **원본 또는 원본 조회 결과를 외부 LLM API 로 보내기 어렵다.** 집계·가공 결과는 **반출 기준을 충족하는 범위에서** 전송할 수 있다. 이 앱은 이 답변을 설계로 구현했다. 화면의 **"LLM 에 보내는 내용 미리보기"** 에서 실제 전송 내용을 그대로 볼 수 있다.

## 한눈에

| 단계 | LLM 에 보내는 것 | 보내지 않는 것 |
|---|---|---|
| 계획 에이전트 | 질문 글, 표 명세(표·열 이름, 형식, 설명, 업종·시간대·읍면동 **코드값 목록**), 분석 기간(연월 두 개), 규칙 기반 1차 해석(의도·동네·업종) | 표 안의 데이터 값 전부(숫자 한 개도 없음), 올린 CSV 의 파일 이름·내용, 내 가게 자료 |
| SQL 수정(실패 시 최대 2회) | 실패한 SQL, DuckDB 오류 메시지, 표 명세 | 데이터 값(오류 메시지에는 열·구문 정보만 있음) |
| 해설 에이전트 | `export_gate` 를 통과한 집계표 중 **반출용 표**(엄격 모드 기본: 지수·비율·순위 열만), 표당 60행 이하, 소수 셀은 "비공개", 데이터 종류(가상/센터·공개), 내 가게는 **비율·백분위·증감률만** | 단순집계(합계·평균·건수, 엄격 모드), 10 미만 수치, 원천 행, 내 가게 월 매출 금액, 차단된 표, 올린 CSV 원문 |
| 오프라인 모드 | **없음**(전송 0건, 호출 0회) | 전부 |

## 구조적 보장
1. 데이터는 로컬 DuckDB 에만 있고, LLM 이 만든 SQL 은 `sql_run` 의 안전 검사(SELECT 만, 허용 표만, 집계·LIMIT 강제, 파일·시스템 함수 차단, 연결 자체가 파일·네트워크 접근 불가)를 통과해야 실행된다.
2. 실행 결과는 `export_gate`(10 미만 억제, 근거 건수 확인, 식별 열 차단, 원천 행 비율 차단)를 통과해야 LLM·보고서로 나갈 수 있다. 통과하지 못한 표는 로컬 템플릿으로 설명하고 LLM 에는 보내지 않는다.
3. 엄격 모드(`config/export_rules.yaml: strict_mode`)에서는 원본 불가 표의 단순집계가 반출용 표에서 빠진다(문서 4쪽 vs 10쪽 충돌에 대한 보수적 처리, 센터 질의 필요).
4. 해설 문장의 숫자는 보낸 표에 있는 값인지 확인한다(단위를 바꾼 값 포함). 표에 없는 숫자가 많으면 LLM 해설을 버리고 템플릿 해설로 대체하고 그 사실을 화면에 적는다.
5. 키는 화면 입력(저장 안 함) 또는 프로젝트 루트 `.env` 에서만 읽는다. 시스템 환경변수·다른 폴더의 키 파일은 찾지 않는다. 제출물에는 `.env.example` 만 있다.
6. 온도 0, 질문당 호출 상한 4회, 호출 수·토큰·예상 비용을 "분석 기록"에 남긴다. 생성된 SQL 은 `runs/plans/` 에 저장해 같은 질문이 같은 SQL 로 재현된다. 분석 기록 파일(`runs/*.json`)에는 데이터 값이 없다.

## 공개 실데이터
`[실데이터]` 단계(버스·BC카드 관광객·도민 유동인구·휴게음식점 등)는 공개 자료이고 `open` 표라 반출 가능 표처럼 취급하지만, 같은 검사를 거쳐 같은 방식으로 LLM 에 간다.

## 확인이 필요한 점
- 지수·순위(응용집계)가 반출 가능하다는 PDF 조항에 맞춘 것이다. 센터가 다르게 해석하면 `config/export_rules.yaml` 만 바꾸면 된다.
- 질문 글에 이용자가 개인정보를 적으면 그대로 계획 에이전트로 간다(미리보기에서 확인 가능). 화면 안내에 "개인정보는 질문에 쓰지 마세요"를 포함했다.
